# Policy: Documentation

Documentation must describe actual behavior.

Distinguish:

- current;
- historical;
- planned;
- experimental;
- deferred;
- unsupported.

Do not:

- document an aspiration as implemented;
- remove limitations because they are inconvenient;
- present source assertions as project facts;
- duplicate authoritative decision logs unless the duplicate improves navigation.

For substantial architecture changes, document problem, constraints, alternatives,
decision, compatibility, migration, failure modes, test strategy, security, and rollback.
